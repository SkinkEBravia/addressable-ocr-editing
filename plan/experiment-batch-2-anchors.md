# 实验批次 2：操作逻辑

> [!abstract] 术语更正
> 批次 1 用的"操作面（operation surface）"是一个含混的复合词。**本批次起统一改称「操作逻辑（operation logic）」**，并拆成下面四个可独立测量的维度。旧文档中的"操作面"一律按本文件的维度重读。

## 1. 变量定义

### 1.1 聚焦机制（focusing mechanism）

分两个阶段，二者可独立变化：

| | **发现阶段**：错误怎么被找到 | **输出阶段**：产出覆盖多大 |
|---|---|---|
| `rewrite` | **自然聚焦** —— 靠思维链自身发现 | **遍历全文**（连续输出，走完整个注意力窗口） |
| `find_replace` | **自然聚焦** —— 同上 | **仅聚焦已发现的错误处** |
| `patch` | **按锚点聚焦** —— 呈现与提示词**强制分块思考**；但真正定位仍靠**块内字符串匹配**（`replace(bN, old, new)` 的 `old`），块 id 只缩小搜索范围 | **仅聚焦已发现的错误处** |
| **`anchored-rewrite`** | **按锚点聚焦** | **遍历全文** |

> [!important] 这是一个 2×2，而第四格目前是空的
> `anchored-rewrite`（看带锚输入 + 必须逐块输出）正好补上空缺格。
> ⇒ 批 1a 的探针**不只是公平性对照，它是设计里的一个真实格子**。

### 1.2 操作丰富度（operation richness）

提供多少种工具。当前只有两档：

| 档 | arm |
|---|---|
| **0 个工具** | `rewrite` / `anchored-rewrite` |
| **1 个工具** | `find_replace` / `patch` / `swe_edit` |

patch 的多操作面（`append` / `merge` / `move` / `set_attrs`）**本批次不讨论**，`hide_ops` 保持隐去。

⇒ 本维度当前与聚焦机制**共变**，不构成独立因子。**记录在案，暂不拆解。**

### 1.3 隐操作（hidden operations）

模型必须默默完成、但工具契约没有明说的工作。

| arm | 隐操作 | 何时出现 |
|---|---|---|
| `rewrite` | 无 | — |
| `find_replace` | 构造唯一匹配串 | 恒有（但失败可被系统拦下） |
| `patch` | 无（锚点照抄） | — |
| **`swe_edit`** | **计算行号区间 + 预判自身前序编辑造成的位移** | **仅在无回显的批量修改下** |

⇒ 隐操作是 **(寻址机制 × 协议)** 的属性，不是 arm 单独的属性。给回显即消除。

### 1.4 编辑粒度（blast radius）—— **批 0 新增，且是主因**

一次**误**编辑毁掉多少字符。

| arm | 编辑单位 |
|---|---|
| `find_replace` | 字符串片段 |
| `patch` | 块内片段（`replace`） |
| `swe_edit` | **整行 / 行区间** |
| `rewrite` | 全文（破坏弥散、不可归因） |

**批 0 证据见 §3.1。这个维度在批次 1 的分析里被完全漏掉了。**

### 1.5 交互协议（不是独立因子，是聚焦机制的修饰）

| 档 | 定义 | 对聚焦机制的作用 |
|---|---|---|
| **B**（batch） | 单轮，一次吐出全部编辑，无回显 | 无重聚焦能力 |
| **S**（sequential-native） | 一轮一条命令 + 每条后回显 | **赋予重聚焦能力** |

- **回显 = 重聚焦能力。**
- `rewrite` 本来就没有重聚焦能力，**有无回显对它应无差别** —— 这是一个可证伪的预测。
- 协议还决定 `swe_edit` 的隐操作是否存在（§1.3）。

### 1.6 处理对象的属性（非操作逻辑）

**噪声水平**：`dta19-l0 / l1 / l2`，共享同一批 11 篇源文档与页码抽样。官方 baseline cMER **0.0040 / 0.0240 / 0.0546**；本仓库 noop 实测 l0=0.0040、l1=0.0242（口径两次对齐）。

### 1.7 指标：选择率（不用 "selectivity"）

**选择率 = 一篇文档里被发起编辑的处数。** 衡量"改了多少地方"。

破坏侧不需要新指标 —— `_decompose_alignment` 已经算好 `fixed / broken / halluc_ins / missed` 四维。

> [!note] 已有轮子，不要重造
> - `datasets/hipe_2026/dataset.py::_decompose_alignment` 内部已算出 `fixed_sub / fixed_del / fixed_ins_del / broken_sub / broken_del / broken_ins / missed_*` **九个分量，但只返回 4 个聚合率**。S/D/I 分解是**暴露**不是计算。
> - `scripts/report_summary.py` 已做 report.json → markdown 表格。
> - 磁带 `turns[].calls[]` + `results[].ok/feedback` 齐全，选择率与 op 失败率可直接算。
> - **patch 计数注意**：一次 `run_patch` 调用内含多行 `replace`，必须按方言行数计，不能按 call 数计。

## 2. 批次 1 遗留的三个缺陷

### 缺陷 A：输入呈现未受控

`present_input` 实测：`rewrite`/`find_replace` = 裸文本；`swe_edit` = `1: …`（`line_number` + `cat_n`）；`patch` = `<x id="b1">…`（`blockkey_as_is` + `xml_ish`）。

⇒ 批次 1 的"操作面差异"混了**能做什么操作 / 看到什么标记 / 标记的分段暗示**。

### 缺陷 B：`patch` 结果作废 —— **atomic 连坐（已定位并修复验证）**

`patch-1turn.toml` 未设 `apply_mode` ⇒ 默认 **atomic**：批次内任一 `replace` 的 `old` 匹配不上（`PATTERN_NOT_FOUND`）即**整批回滚**。

磁带实测（全部失败都是 `PATTERN_NOT_FOUND`，**零条 `KEY_NOT_FOUND`、零条解析错误**）：

| run | 提交 op | **每-op 失败率** | **因 atomic 作废的 op** |
|---|---|---|---|
| `dta19-chunk-1t` | 1024 | 1.27% | 19.5% |
| `dta19-doc-1t` | 262 | 0.76% | 29.8% |
| `dta19-l1-doc-1t` | 3339 | **0.24%** | **83.7%** |

典型：`第 229 条失败 / 共 774 条` ⇒ 773 条正确修复全部作废。

> **patch 的单条定位精度是全场最好的**（l1 每-op 失败率 0.24%，比 find_replace 的 1.7% 好 7 倍）。是 atomic 把单点失败放大成整批损失。

#### best_effort replay 验证（零 API，`runs/*-be`）

| l1，noop=0.0242 | cmer | fixed | broken | halluc |
|---|---|---|---|---|
| patch atomic | 0.0209 | 0.2027 | 0.0015 | 0.0008 |
| **patch best_effort** | **0.0112** | **0.7097** | 0.0041 | 0.0024 |
| 变化 | **−46.4%** | **3.50×** | 2.73× | 3.0× |

⇒ **H-J 成立：被作废的 op 绝大多数是对的。批次 1 中所有关于 patch 的结论作废。**

> [!warning] 措辞纪律
> l1 的配对检验中四臂**彼此全部 CI 跨 0**（rewrite vs patch `+0.00097 [−0.00223,+0.00449]`；patch vs swe_edit `−0.00146 [−0.00306,+0.00003]`）。
> **只能说"patch 从显著垫底恢复到与其余持平、均值最优"，不能说"翻到第一"。** n=11 撑不起更强的话。

#### 一个讽刺的观察（值得进论文）

l0 上 patch 的 **atomic 版（0.0047）反而优于 best_effort 版（0.0051）** —— 连坐 bug 让它少做事（fixed 0.2072 vs 0.2728），而在错误率仅 0.4% 的文本上"少做事"本身就是优势。

**一个纯粹的实现缺陷，在低噪声下伪装成了良好的设计。** 若不做跨噪声级比较，这个 bug 可能永远不会暴露。

### 缺陷 C：swe_edit 的破坏来自粒度，不是地址失稳（**假说已修正**）

原假说（地址在批次内失稳）**被批 0 证伪**，见 §3.1。

## 3. 批 0 结果（已完成，零 API 成本）

分析脚本在 scratchpad，只读运行于主 checkout；**未改动仓库任何文件**。覆盖 759 盘磁带 / 5 个 run。

### 3.1 编辑粒度是主因，地址失稳不是

| run | swe_edit 编辑/批次 | broken | 判读 |
|---|---|---|---|
| `dta19-doc-1t` | 42.3 | **0.0285** | 灾难格 |
| `dta19-l1-doc-1t` | 74.9 | 0.0054 | **编辑更多，破坏低 5 倍** |
| `dta19-seq-local` | **1.0** | 0.0070 | **每批次仅 1 次编辑，仍是同 run 最高** |

seq 那行决定性：**批内位移不可能发生，broken 仍是 find_replace 的 2.6 倍。**

同格对照（`dta19-doc-1t`，编辑数几乎相同）：

| arm | 编辑单位 | 编辑数/篇 | broken |
|---|---|---|---|
| `find_replace` | 字符串片段 | 47.4 | **0.0027** |
| `swe_edit` | **整行 / 行区间** | 42.3 | **0.0285** |

**编辑数相当，破坏差 10 倍 ⇒ 差的是每次误编辑的破坏面积。**

（`r(编辑数, broken)` 在 l0-doc 的 swe_edit 达 **+0.904**，但那是格内效应；跨格比较显示编辑数不是主因。原假说把格内相关误当成机制。）

### 3.2 失败可检测性：强证据

> [!warning] 口径更正
> 初版此表把 patch 的**整批失败率**（分母 = 批次，一批含数百条 op）与 find_replace 的**单条失败率**（分母 = 单条 op）并排比较，是错的。下表统一为**每-op 口径**。

| arm | **每-op 失败率**（chunk / doc / l1-doc） | 拦截机制 | broken |
|---|---|---|---|
| `find_replace` | 1.4% / 1.3% / 1.7% | `PATTERN_NOT_FOUND` | 低 |
| `patch` | **1.27% / 0.76% / 0.24%** | `PATTERN_NOT_FOUND`（`old` 不匹配） | 见缺陷 B |
| **`swe_edit`** | **0.0% / 0.0% / 0.0%** | **无** | **最高** |

**按每-op 口径，patch 的定位精度全场最好**（l1 的 0.24% 比 find_replace 的 1.7% 好 7 倍）；它之前看起来差，是 atomic 连坐（缺陷 B），不是定位能力。

**而 `swe_edit` 的 0.0% 恒定才是要点：行号地址永远合法，系统一次都拦不住。**

⇒ **粗粒度 + 不可检测 = 最危险的组合。** 两条互补，不竞争。

### 3.3 dta19 完整结果（patch 全部已修正为 best_effort）

> 四个 run 的 patch 臂原以 `apply_mode=atomic` 运行，已用磁带重放修正（见缺陷 B）。
> `seq` 系列的 `patch_seq` / `patch_global_seq` 本就是 best_effort，未受影响。

| 噪声 | 形态 | noop | rewrite | find_replace | swe_edit | **patch** |
|---|---|---|---|---|---|---|
| **l0** 0.0040 | chunk | **0.0040** | 0.0127 | 0.0070 | 0.0089 | 0.0079 |
| **l0** 0.0040 | doc | **0.0040** | 0.0075 | 0.0050 | 0.0289 | 0.0051 |
| **l0** 0.0040 | seq-local | **0.0040** | 0.0062 | 0.0050 | 0.0093 | 0.0059 |
| **l0** 0.0040 | seq-global | **0.0040** | — | 0.0058 | 0.0097 | 0.0060 |
| **l1** 0.0242 | doc | 0.0242 | 0.0122 | 0.0127 | 0.0127 | **0.0112** |
| **l1** 0.0242 | seq-local | 0.0242 | 0.0122 | **0.0100** | 0.0123 | 0.0149 |
| **l2** 0.0580 | doc | 0.0580 | 0.0560◊ | 0.0276 | **0.0258** | 0.0291 |
| **l2** 0.0580 | seq-local | 0.0580 | 0.0238 | **0.0198** | 0.0307 | 0.0236 |

◊ `rewrite` 在 l2-doc 有 **5/11 `failed:incomplete`**，回退原文，见下。

#### 三个噪声档 = 三种局面

| 档 | 结论（配对检验，n=11） |
|---|---|
| **l0** | **不修最好**。doc 下仅 `patch`/`find_replace` 与 noop **打平**（CI 跨 0），`rewrite`/`swe_edit` **显著有害**；**chunk 下四臂全部显著差于 noop** |
| **l1** | 四臂**全部显著优于 noop**，但**彼此统计不可分**（patch 均值最优 0.0112） |
| **l2** | 三个编辑臂**全部显著优于 noop 且彼此不可分**；**`rewrite` 崩** |

#### l0 的 doc vs chunk 分叉（新发现）

同为 l0，**整篇输入**时 `patch`/`find_replace` 能与 noop 打平；**切成孤立块**后四臂全部显著差于 noop。

⇒ **低噪场景下切块本身是有害的** —— 缺少跨块上下文，模型更容易把正确文本误判为错误。
这对 §1.1 的"发现阶段聚焦"是直接证据：自然聚焦的质量依赖可见上下文的完整性。

#### `rewrite` 在 l2 的失败模式：写不完，不是写不好

| 状态 | 篇数 | cmer |
|---|---|---|
| `done` | 6 | 0.0187 / 0.0197 / 0.0229 / 0.0241 / 0.0262 / 0.2139 |
| **`failed:incomplete`** | **5** | 回退原文（≈ noop） |

完成的 6 篇里 5 篇落在 **0.019~0.026**，与最优臂持平。

⇒ **这是「输出遍历全文」这一聚焦机制的容量约束**（§1.1）。l2 错误密度 ~5.8%，模型既要复现
~14.4k 字符又要密集修复，输出长度撞预算。**高噪 + 长文档下，全文重写不是变差，是不可行。**

而在 `seq-local` 形态（每轮只重写一个 chunk）下 `rewrite_seq` 恢复到 0.0238 —— **切块解除了容量约束**。
与上面 l0 的结论合起来：**切块在低噪有害、在高噪对 rewrite 必需**，这本身就是一条 regime 规则。

#### 选择率（提交的编辑处数 / 篇）

| run | rewrite | find_replace | swe_edit | patch |
|---|---|---|---|---|
| l0-doc | 0（隐式全文） | 47.4 | 42.3 | 23.8 |
| l1-doc | 0（隐式全文） | 202.1 | 74.9 | 303.5 |

⚠️ **口径注意**：`patch` 按 `fn` 方言行数计（一次 `run_patch` 调用含多行 `replace`），
其余按调用数计。`rewrite` 无显式 op，其选择率必须由 **input↔output 对齐**算出 —— 待补（批 0.5-0f）。

#### 口径备注

- dta19 的 **doc 级评分走 fallback**（`chunks_aligned=0` ⇒ 整篇 micro cMER），因为页内含 `\n`，
  按分隔符切不回 10 个单元。**各臂口径一致，arm 间比较有效**；但**不得与 en5 的 doc 数字
  （chunk-mean）混排**。
- noop 实测 vs 官方 baseline：l0 **0.0040 / 0.0040** ✅、l1 **0.0242 / 0.0240** ✅、
  l2 **0.0580 / 0.0546** ⚠️（差 6%，疑与上述 fallback 口径有关，**待查**）。

## 4. 统一口径决定

### 4.1 行号锚对齐原生 SWE-agent classic

依据 `related_agents/swe-agent-classic/config/`。

| 原生机制 | 现状 | 决定 |
|---|---|---|
| **一次响应一条命令**（"one discussion and one command EXACTLY"） | 单轮可批量 | ✅ 对齐 ⇒ 协议档 S |
| 每次 edit 后回显更新窗口 | 有回显，单轮下无用 | ✅ 对齐（S 档自动生效） |
| 失败时明确"DO NOT re-run the same failed command" | 无 | ✅ 加进提示词（零成本） |
| `edit <s>:<e>` + heredoc `end_of_edit` | `edit(s, e, "JSON")` | ⚠️ **R1 待定** |
| **linter 门禁**：语法错 ⇒ 拒绝应用 + 回显原文 | 无 | ❌ 散文无等价物 |
| **WINDOW=100 行滑窗** + open/goto/scroll | 整篇呈现 | ❌ 故意不对齐 |

**不做窗口**：(1) 会同时改变可见上下文 —— 那是视图粒度那条线的变量；(2) `patch`/`find_replace` 都看全篇，加窗口破坏呈现对等，重蹈缺陷 A。

> [!note] linter 缺失可直接写进论文，且批 0 给了它数据
> 原生 SWE-agent 的行号锚安全性**依赖 linter 门禁**。散文没有可机械校验的语法 ⇒ **op 失败率恒为 0%（§3.2），系统完全无法拦截误编辑**。这解释了一个在 SWE-bench 上可用的工具为何在 OCR 修复上垫底。

### 4.2 anchored 条件的输出契约

带锚输入 ⇒ **要求输出也带锚**，由系统剥离。

| arm | 与锚的关系 | 出错后果 |
|---|---|---|
| `anchored-rewrite` | **必须复现**全部锚 | 缺失/重复/乱序 → 结构校验失败（响亮，**单独计数**） |
| `patch` | **必须引用** | `KEY_NOT_FOUND`（响亮） |
| `find_replace` | **必须忽略** | 锚写进 `old` → `PATTERN_NOT_FOUND`（响亮） |

**新增计量 `anchor_structure_ok`；不得混进 `broken_rate`。**

⚠️ 三个臂与锚的关系是三种（复现 / 引用 / 忽略）。**统一呈现只保证输入相同，不保证任务难度相同** —— 论文必须写明。

### 4.3 patch 的预算（R2 待定）

| 方案 | 做法 | 代价 |
|---|---|---|
| **P-multi**（推荐） | 改多轮（参照 `en5-doc-patch8t`） | 与 B 档"单轮"定义冲突 ⇒ 只能放 S 档 |
| **P-budget** | 抬高单轮 `output_length` | 破坏跨臂 token 预算一致性 |

**推荐 P-multi**：天然落进 S 档，B 档只留能单轮完成的臂。但 §3.2 显示 patch 在 l1 有 **40% op 失败率** —— **多轮 + 回显能否把它降下来，本身就是一个值得测的问题。**
