## 1. 中心不可分、尾部分得开：跨版本保持

v4.1 中位跨度 0.0078~0.0119（**1.5×**），max 跨度 0.0276~0.7483（**26×**）。
v4 是 1.4× / 33×。同向同量级。

最优臂仍是 `patch-find-replace`（中位 **0.0078**、max **0.0284**，双料最优，
且优于 v4 的 0.0084 / 0.0295）。最差中位仍是 rewrite 系（0.0104 / 0.0119）。

⇒ 09-08 批次结论 1（接口差异在中心趋势上分辨不出、尾部差一个数量级以上）
**在模型版本升级后保持**。

## 2. 唯一显著的配对变化：注意力条款对 find_replace 由亏转盈

`find-replace-blocked` 是唯一 CI 不跨 0 的配对：**Δcmer −0.0075 [−0.0129, −0.0029]，
fixed +12.2pp**。

v4 批次结论 5 说「注意力控制对 `find_replace` 是净亏」（fixed −3.0pp、out tok +21%）。
v4.1 上同一对照（numkey → blocked）：fixed **58.0% → 60.2%（+2.2pp）**，
out tok **1.47M → 1.46M（持平）**——不亏反赚。

⇒ 「先按块想再发散值不值」**是模型版本相关的结论，不是接口的性质**。
对 v4 成立的负收益断言不能外推到 v4.1。

## 3. `key_leak` 破零：单样本泄漏 244 次

v4 八单元全场 0.00%；v4.1 `rewrite-numkey` 的 `dta19-l1/1828-platen_gedichte`
泄漏 **244 次**（该样本 cmer 0.1042、broken 10.9%），同一臂均值被拉到 739%。

均值具有欺骗性：**33 篇中 32 篇 key_leak 仍为 0**，中位 key_leak 仍为 0。
v4 在同一篇同一臂上干净（cmer 0.0103，无泄漏）。

09-08 批次结论 7 的跑前预期是「`rewrite` 最可能把 key 抄进产出」——
在 v4 落空，**在 v4.1 兑现了一次**，且恰恰落在 rewrite 系。
泄漏脆弱性是模型版本相关的；「共享 view description 的防漏声明永远够用」不再成立。

## 4. 灾难样本换了位置

v4 `rewrite` 的灾难样本 `dta19-l1/1897-poersch_gewerkschaftsbewegung`（cmer **0.9648**）
在 v4.1 上修复到 **0.0088**；v4.1 的尾部最差挪到 `rewrite-numkey` 的泄漏样本
（0.7483，见上条）。`rewrite` 配对 Δ −0.0306 [−0.0901, +0.0010] 擦边跨 0——
方向是改善，但两边都由单样本驱动，**证据强度不足以断言 rewrite 的灾难模式已修复**。

## 5. 账单：out tok 省 1/3 ~ 1/2，省的全是 reasoning

全场 out tok 从 2.1~2.6M 降到 1.0~1.5M（−32% ~ −47%，rewrite 臂砍半 1.88M→0.99M），
reasoning 占比从 89~93% 降到 83~88%。**可见输出（out−reasoning）中位与 max 基本不变**
（≈4~6k / 24~31k，两臂对照见 Dump/compute_v41_report.py 输出）。

⇒ v4.1 在同预算（384k）下完成同样的编辑，思考开销大幅收窄。
token 效率结论要按版本分别陈述；若单价不变，这批单元直接省 1/3 以上费用。

## 缺口

- **泄漏是单样本**。结论 3 的强度 = 「能发生」，不是「会频繁发生」；n=33 里没有第二个。
- **3 格 `budget_exceeded`**（pfr 1、unstable 2）：响应未以 `done()` 收尾，产出照常评分，
  对 fixed/broken 口径无影响，但对「v4.1 的指令收尾纪律」是一个小信号。
- **尾部仍只有描述统计**（同 09-08 缺口）；结论 1 的 26× 未做检验。
- **跨模型证据未齐**：OpenRouter GLM 5.3 / Packy Grok 4.6 两批次仍在跑，
  它们的报告与本文档互为模型对照（口径差异：GLM 批次 provider 按单元分配）。
