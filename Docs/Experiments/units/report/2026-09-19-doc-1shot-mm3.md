## 1. 头条：契约遵循率按接口族分裂——工具方言崩、rewrite 全合规

六个工具方言臂的 done 率 **1~15/33**，两个 rewrite 臂 **33/33**。
`budget_exceeded`（1-shot 下 = 响应未以 `done()` 收尾）是纯粹的模型行为：
回放实测 `stop_reason=end_turn`，output token 散布 2~16k、远低于 384k 预算，
**端点无截断**（max_tokens=393216 正常接受）。

失败模式分类（202 个 budget_exceeded 格子，按响应文本特征）：

| 单元 | 失败模式分布 |
|---|---|
| `patch-find-replace` (29) | 长篇未 done 收尾 15；发一条调用即停 12；幻觉工具回显 1；思考漏入可见文本 1 |
| `find-replace` (18) | 发一条调用即停 9；长篇未 done 收尾 9 |
| `find-replace-blocked` (29) | 发一条调用即停 16；长篇未 done 收尾 12；done 缺括号 1 |
| `find-replace-numkey` (29) | 发一条调用即停 25；长篇未 done 收尾 4 |
| `patch-find-replace-noatt` (24) | 发一条调用即停 14；长篇未 done 收尾 8；done 缺括号 2 |
| `patch-find-replace-unstable` (32) | 长篇未 done 收尾 16；发一条调用即停 15；done 缺括号 1 |

三类典型违约：(a) **发一条 `read` 就 end_turn**（<50 tok，等 harness 返回——
agentic 训练的肌肉记忆）；(b) **自己幻觉工具回显**（输出里编造 `<num-key>: N`
块）或把 `<thinking>` 漏进可见文本；(c) 写分析散文作前导、调用用原生 JSON 风格
（`find_replace\n{"path":...}`）、`done` 不带括号。

⇒ 1-shot 文本方言协议隐含假设了「非 agentic 的指令遵循」；agentic RL 模型会把
模拟工具调用的方言当成真实工具调用。这是**实验范式的边界条件**，是本批次最
重要的发现。rewrite 臂全合规（全文重写不模仿工具调用）构成天然对照。

## 2. 工具臂指标塌缩到 noop 水平；合规 ≠ 编辑

工具臂中位全部落在 0.0232~0.0238（= noop 锚点），fixed 0.0~11.4%、spans
0.0~59.9——多数格子的产出**没有任何有效编辑被执行**。配对显著变差
（Δcmer +0.010~+0.018）由不合规驱动，**不能读作「M3 编辑质量差」**。

合规子集内部还有第二层分化（done n / done 中位）：

| 单元 | done n | done 中位 | 性质 |
|---|---|---|---|
| `find-replace-blocked` | 4 | **0.0060** | 真编辑，且质量优于 v4 全样本中位（0.0105） |
| `patch-find-replace-unstable` | 1 | 0.0194 | n=1，仅供参考 |
| `patch-find-replace-noatt` | 9 | 0.0202 | 部分空跑 |
| `find-replace` | 15 | 0.0238 | 含直接 `done()` 空跑（中位 = noop） |
| `patch-find-replace` | 4 | 0.0284 | 含空跑 |

⇒ 当 M3 履行契约且真编辑时，num-key + 注意力条款的接口在它身上照样工作
（blocked 合规子集 0.0060 甚至是全序列该臂最好数字）。但 n≤9，只够证明
「能工作」，不够支撑臂间排序。**工具臂的臂间排序问题在 M3 上无解**——
不是噪声大，是样本没了。

## 3. rewrite 两臂：完全合规、中心持平、尾部与 broken 恶化

rewrite 中位 **0.0097** 与 v4/v4.1 的 rewrite（0.0104 量级）持平，配对跨 0
——**全文重写接口在 M3 上中心趋势无损**。但两个尾部信号：

- 灾难样本 `dta19-l2/1804-paul_flegeljahre01` 在**两个** rewrite 臂同时炸
  （0.7342 / 0.7357，broken 13~14%）；
- 臂级 broken 率 9.24% / 14.25%，远高于 v4.1（0.65% / 9.91%）——
  rewrite 系「重写即破坏」的已知弱点在 M3 上放大。

## 4. key_leak 从单样本事件升级为系统性：0/33 → 1/33 → 10/33

| 批次 | rewrite-numkey 泄漏样本数 | 单样本最大泄漏次数 |
|---|---|---|
| v4 | 0/33 | 0 |
| v4.1 | 1/33 | 244 |
| **mm3** | **10/33** | **308** |

且**只有 rewrite-numkey 泄漏**：mm3 的 rewrite（无 num-key 视图）0/33，
六个工具臂 0/33。「never include keys」契约的遵守是**模型（版本）特性 + 视图
触发**的交互：num-key 视图给全文标了序号，全文重写时把序号一并抄出——
09-08 批次的跑前预期（rewrite 最可能漏 key）在 v4 落空、v4.1 兑现一次、
**M3 上系统性兑现**。均值 7758% 由 10 个泄漏样本撑起，中位仍为 0。

## 5. 灾难样本第三次换位

v4 的 `l1-poersch`（0.9648）→ v4.1 修复到 0.0088；v4.1 的 `l1-platen`
（0.7483，泄漏样本）→ mm3 上 rewrite 两臂该篇 cmer 0.0504 / 0.1399；mm3 的
尾部最差挪到 `l2-paul_flegeljahre01`（0.7342/0.7357）。**每个模型的灾难样本
位置不同**——尾部风险是模型特性，不是文档内在难度。逐样本归因见各单元磁带。

## 6. 账单：总 output token 低一个数量级，但口径不可直比

mm3 全场 0.14M~1.13M，v4 是 2.1~2.6M（90%+ reasoning）、v4.1 是 1.0~1.5M。
两点警示：(a) anthropic 口径不单列 reasoning，`reasoning_tokens=None`，
无法拆分「思考 vs 可见」；(b) 工具臂的低 token 主因是**失败格子太短**（早停），
不是效率。唯一有意义的对比是 rewrite 臂（全合规）：0.57M vs v4 1.88M /
v4.1 0.99M——即便其中含 reasoning，总量也省了 40~70%。

## 缺口

- **端点/协议未控制**：首个 anthropic 协议批次，system 顶层字段下发；显著偏离
  应先归端点/协议再归模型（本报告的「模型行为」断言都带这个星号）。
- **工具臂合规子集 n≤15**（四个臂 n≤4）：配对显著性由不合规驱动；合规子集
  指标有自选样偏差，臂间排序无解。
- **配对 CI 的读法**：工具臂「显著变差」= 「大多没编辑」，不是编辑质量差异；
  报告正文已按此口径陈述，引用配对表时须带这句。
- **尾部仍只有描述统计**（同前两批）。
- **跨模型证据未齐**：OpenRouter GLM 5.3 / Packy Grok 4.6 两批次暂停中，
  与本文档互为模型对照。
