## 一、评测指标与加权规则

### 1. 核心指标定义

- **主指标（Primary Metric）**：`Overall micro-cMER`（微平均字符错误率）—— 各测试集 cMER 的加权平均值，**越小越好（↓）**。
- **次级指标（Secondary Metric）**：`Overall macro-preference`（宏平均偏好胜率）—— 各测试集偏好分数的加权平均值，**越大越好（↑）**。
  - 偏好分数（Preference Score）：衡量模型输出相比于原始 OCR（baseline-no-correction）是变好还是变差。
  - 计算方式：$\text{Pref} = \frac{N_{\text{improved}} - N_{\text{degraded}}}{N_{\text{total}}}$，取值范围 $[-1, +1]$。正值表示改善样本多于劣化样本，负值表示“越修越差”。
- **辅助指标**：
  - `cMER macro`：逐样本 cMER 的算术平均。
  - `wMER macro`：逐样本词错误率（Word MER）的算术平均。

### 2. 权重设计（Design Weights）

官方不是按语料字符规模加权，而是按数据集设计权重：
- **非 DTA 测试集**（5 个）：各占权重 **1.0**。
  - `icdar2017-en`, `icdar2017-fr`, `impresso-snippets-de`, `impresso-snippets-en`, `impresso-snippets-fr`
- **DTA19 测试集**（3 个退化级）：各占权重 **1/3（≈ 0.3333）**。
  - `dta19-l0`, `dta19-l1`, `dta19-l2` 作为一个整体数据集贡献权重 1.0。
- **总权重**：$1 \times 5 + \frac{1}{3} \times 3 = 6.0$。

## 二、参赛团队与方案概述

| Team ID | 机构/背景 | 核心方法与技术路线 | 提交 Run |
|---|---|---|---|
| **baseline-no-correction** | 官方基线 (`noop`) | 严格保留原始 OCR 输入文本，不做任何修改。作为所有系统对比的黄金分水岭。 | run1 |
| **bnf-mistral** | 法国国家图书馆 (BnF) | **历史语料持续预训练 + 合成噪音微调 + 裁判回退防线**：<br>1. 基于 Mistral 架构在 80B Token 历史语料上预训练；<br>2. 使用合成 OCR 噪声进行 LoRA 指令微调；<br>3. 设立单独的 Judge-and-Retry Loop（Anti-hallucination），对大范围改动或疑似幻觉执行**硬性拒绝并回退（Fallback to OCR）**。 | run1, run2, run3 |
| **blocr** | BLOCR 团队 | **通用大模型提示词零样本重写（Prompt-only Zero-shot Rewrite）**：<br>采用严密的 Prompt 指令让大模型直接自回归重写整个文本，代表了无专用后处理微调与无外部校验的纯 LLM 提示词基线。 | run1 |
| **l3i** | L3i 实验室 | 基于序列到序列与开源小模型微调方案，关注字符级纠错。 | run1, run2 (部分) |
| **Zakaria-ENSIAS** | ENSIAS 团队 | 采用开源多语言大模型进行微调的修正尝试。 | run1 (部分) |

## 六、关键学术发现与工程启示

### 1. 低噪声状态下的“过修陷阱”（Overcorrection Dilemma）
- 在中高退化级（如 `dta19-l1`, `dta19-l2`, `icdar2017` 等，基准错误率 > 2%）上，几乎所有系统都显著优于 `noop`，Preference score 普遍达到 +0.8 ~ +1.0。
- 然而在极低噪声的 `dta19-l0`（基准错误率 ~0.4%）上：
  - **`noop` 排名第 2**，击败了 5 个团队提交的 6 个系统配置；
  - 纯 Prompt 重写系统 `blocr` 的 cMER 直接从 0.0040 翻倍劣化至 0.0076，偏好分为 **-0.7000**（70% 的文本块修改后比原文更差）；
  - **原因在于非对称风险**：1,000 字里仅 3~4 处瑕疵，大模型自回归生成哪怕带来 0.5% 的随意润色、拼写现代化（Fraktur 特征丢失）或标点变动，都会把原有正确的字符改错（`broken`），其损失远超修对（`fixed`）的收益。

### 2. 为什么 BnF-Mistral 能在全场称雄？
论文与代码揭示了 BnF 团队获胜的三大杀手锏：
1. **历史语料持续预训练**：80B tokens 避免了将古德语、古法语“平滑化/现代化”为当代语言的通病。
2. **Anti-hallucination 裁判模型与拒改回退（Fallback）**：
   设立独立裁判模块对输出进行合法性判定；如果字符编辑距离变化超过阈值（如 >15%）或判定为内容丢失/妄想，**直接丢弃模型修改，回退使用原始 OCR 文本**。这一防线将幻觉率从 42% 强力压制到 6%。
3. **Run 之间的取舍**：
   - `run1`：全面激进修复，在中高噪声集上冲到最高分，总榜夺冠；
   - `run2`：最保守版本，增加了高惩罚的拒改防线，在 `dta19-l0` 上成为全场唯一跑赢 `noop`（0.0029 vs 0.0040）的提交。

### 3. 对本项目智能体架构（Batch-Doc-Process-V2）的直接指导
- **工具编辑范式（Patch / SWE-edit / Find-and-Replace）的天然优势**：
  相较于 `blocr` 式的全局重写（Rewrite），工具交互模式限定了模型只能修改显式指定的锚点/范围，从物理结构上杜绝了对无错误区域的无意识自回归改写。
- **低错误率必须引入“保真偏置（Preservation Bias）”**：
  在 Prompt 中必须强调高置信度门槛，对不确定的历史拼写禁止臆测修改；当置信度不足时，保持原样（宁缺毋滥）才是战胜 `noop` 的唯一途径。
