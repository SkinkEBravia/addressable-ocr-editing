# 实验边界与补实验优先级

这份清单基于已存的 24 个 run/report.json；下面的补实验是建议，尚未执行。
此次修订只做离线分析、写作和图表重建，没有新调用模型 API。

## 当前可以支持的表述

- 这是三个模型/端点配置、八个接口、33 个配对任务的探索性研究。
- 33 个任务来自 11 篇独立源文档的三档噪声，不能当成 33 篇独立文档。
- V4 local 的观察到的尾部小于 rewrite；V4.1 方向相同但差距较小。
- 固定带 key 视图和 attention 后，V4 的 scope 配对均值和 P90 区间不跨零；V4.1 跨零。
- 无 attention 的 scope 配对则是 V4 均值区间跨零、V4.1 不跨零。
- V4 带 key 的视图/提示配置降低了纠错率；edit spans 的区间跨零。
- M3 的单轮文本调用协议遵循存在问题。其最终结果可以作为端到端性能评价，
  但不能据此推出“模型不会用局部编辑工具”或只给成功会话评分。

## 优先补什么

1. **重复关键 2×2 对照，并扩大独立文档数。**
   先锁定 global/local × attention off/on 四臂，固定实际视图和工具语义，
   每个文档/接口记录多次独立采样；另留未参与接口开发的文档作确认集。
   增加两个类似模型并不替代这些重复。分析应区分文档、噪声档、推理重复，
   不把全部输出当独立样本；provider 不支持 seed 时记录调用时间及设置。

2. **核查评分单元与文本保真。**
   当前 loader 用换行拼页，而页内也有换行，触发整篇评分回退，noop 亦然。
   这不使现有整篇 cMER 无效，但与“逐页平均”和官方 leaderboard 不等价。
   新确认实验应先固定评分设计；保留历史整篇结果，另报告页级/官方口径的可比结果，
   不在同一个表中默默替换评分。补充未归一化的文字、标点和版式保真检查。

3. **审计所有尾部失败，而不只列最大值。**
   从既有 tapes 检查每个恶化文档：漏抄、重复、泄漏 key、截断、输出抽取问题、
   parse error、调用拒绝，区分模型输出错误与 harness 错误。
   报告相对 noop 的恶化率和幅度，并做按源文档留一法敏感性分析。
   最大值在 n=33 时非常不稳定，不能解释为安全保证。

4. **把 presentation 的机制实验拆开。**
   新对照保持同一 backend、replacement 语义和 instruction，分别改变 key 的可见性、
   key 说明文字和 key 是否可寻址；需要时增加等长占位标记对照。
   当前结果是实现配置效应，不能断言“非信息行号本身造成保守”。

5. **单独验证 M3 的协议适配。**
   比较单轮文本调用、原生结构化工具调用、有限次数修复反馈。
   报告 parse/call/status/有效编辑四种指标及代价；单纯 done 不等于调用全成功。
   预先固定预算，保留所有会话，避免只比较成功子集。

6. **再扩展泛化与成本。**
   优先另一个语言/体裁与独立测试集，而不是无限增加同系列模型。
   现有 CSV 有 provider token 计数，可描述性分析；若要声称效率，需统一
   reasoning/token 口径，并记录延迟、价格、重试与实际输出上限。

## 发布材料仍缺什么

派生 CSV 可重建统计与图表，但不能证明评分或重放预测。
还需归档原始报告、模型输出、tape 引用的消息 blob、配置和版本信息，
并验证数据分发条款。署名、单位、最终仓库/归档 URL 也需补齐。
正文已删除对这些未发布原始产物“已经 release”的承诺。
